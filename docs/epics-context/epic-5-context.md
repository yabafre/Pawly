## Architecture references

- Patterns to respect (architecture.md § Communication Patterns, § Data Layer): non-negotiable data flow `Page (RSC) → Client Component → Hook → Zsa (useServerActionQuery/Mutation) → Server Action ('use server') → tRPC Client → NestJS Service → Prisma`. No direct Prisma from `apps/web`; no direct tRPC from client components; Server Actions are the only bridge. Validation single-sourced in `@pawly/validators` (Zod). Clinic domain logic stays in `apps/api/src/modules/clinic/clinic.service.ts`. Prisma 7.2.0 schema-folders (`apps/api/prisma/schema/*.prisma`, columns `@map` snake_case). Writes are `subscribedProcedure + adminOnly`, except onboarding which uses `protectedProcedure`. Always invalidate React Query keys via `QueryKeyFactory` after mutations.
- ADRs in scope: none (architecture predates the APED council/ADR process — architecture.md § Phase 2b).

## Lessons applicable

- **L1** (apps/web Zsa hooks): Server Actions wrapped by Zsa return `[data, err]` tuples; `mutateAsync()` returns directly. Audit each call site for the right destructuring (`useClinicOperationalConfig` / `clinic-operational-config-actions`).
- **L4** (implementation, third-party SDKs): consult Context7 (`/prisma/docs`) before the Prisma migration; don't code from memory.
- **L5** (monorepo build): SWC build emits no `.d.ts`; the `tsc --emitDeclarationOnly` pass in `apps/api` is load-bearing — don't touch it. The pre-existing `@pawly/api/trpc-types` `AppRouter` type error in local `tsc` is this artefact, not new breakage.
- **L2** (QA gate): unit/integration tests don't replace real user-journey testing — do the visual pass (toggle 24/7 in wizard + settings, confirm persist) before declaring `review`.
