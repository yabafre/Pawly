### Story 7-6-post-publication-change-management — done 2026-07-08T21:20:00Z

- **Decisions:** Post-publication guard is a defense-in-depth pair — server throws `PUBLISHED_CHANGE_REQUIRES_ACK` (source of truth), client `usePublishedChangeGuard` stash-and-confirm dialog is UX only. Notifications ignore `notifyOnPublish` on purpose (missed change = missed shift). Push is decoupled from email presence (an active null-email employee still gets push). Any shift mutation must invalidate the `publication-status` React Query key, not only schedule keys, or the amended badge goes stale.
- **Files:** validators `shift-mutation.schema.ts`/`equity-alert.schema.ts`; api `PlanningPeriodStatus.prisma`, `mail-i18n.ts`, `mail.service.tsx`, `templates/ScheduleChangedEmail.tsx`, `trigger/tasks/send-email.ts`, `planning-generation.service.ts`, `planning.router.ts`; web `usePublishedChangeGuard.ts`, `useShiftMutations.ts`, `PublishedChangeDialog.tsx`, `ScheduleViewWrapper.tsx`, `PlanningHealthBar.tsx`, `i18n/langs/{fr,en}.json`.
- **Contracts:** `acknowledgePublishedChange: boolean` (default false) on all three shift-mutation inputs; `amendedAt`/`amendmentCount` added to `PlanningPeriodStatus` + `publicationStatusResultSchema` + `getPublicationStatus`; 12th email type `schedule-changed`. React Query key `["planning","publication-status",month]` must be invalidated by shift mutations.
- **Deviations from plan:** Review found the mutation hooks did not invalidate the publication-status query (amended badge stayed stale in-session) — fixed. Push notification was coupled to email presence (null-email active employee got neither channel) — decoupled. Both fixed under commit `763a441`, live-verified via next-browser. Bulk-regeneration guard bypass, non-transactional amendment, and email-fallback are confirmed real but out of 7-6 scope — deferred to Epic 11 (11-1 / 11-6 / 11-4).
