## Critical Bugs Discovered

### Bug #1: Admin Registration Uses Magic Link Instead of Password Creation (ARCHITECTURE DEVIATION)

**Severity:** CRITICAL
**Location:** `apps/api/src/modules/stripe/stripe-webhook.controller.ts` — `handleCheckoutSessionCompleted()`
**Root Cause:** The webhook calls `authService.requestMagicLink(adminEmail)` which is the employee auth path. The Architecture (line 105) and PRD (line 101) specify: "Auth Strategy: Exclusive Magic Link for employees (no password) and hybrid (Password/JWT + Magic Link) for admins."

**Evidence:**
- Architecture.md: `Auth Strategy: Exclusive Magic Link for employees (no password) and hybrid (Password/JWT + Magic Link) for admins.`
- PRD NFR7: `Admin passwords must meet minimum complexity (8+ chars, mixed case, numbers).`
- The login page (`LoginPageClient.tsx`) already has two tabs: Magic Link + Password — confirming dual-auth was designed.
- `User.prisma` has `password String?` (nullable) — the model supports it.
- `auth.service.ts` has `validateUser()` with bcrypt — the backend supports it.
- BUT: The checkout webhook sends a magic link, so admins never create a password.

**Required Fix:** Replace `requestMagicLink()` in webhook with an account activation email containing a link to a new password-creation page. After creating their password, admins use the Password tab of the login page.

### Bug #2: TypeError on "Manage Subscription" Button

**Severity:** CRITICAL
**Location:** `apps/web/src/app/[locale]/admin/billing/_hooks/useBilling.ts:35`
**Root Cause:** Incorrect destructuring: `const [result, err] = await portalMutation.mutateAsync({...})`. TanStack Query's `mutateAsync()` returns the data directly (not a `[data, error]` tuple like Zsa). This causes `TypeError: (intermediate value) is not iterable`.

**Required Fix:** Change to `const result = await portalMutation.mutateAsync({...})` with try/catch for error handling. Audit all hooks for the same pattern.

### Bug #3: subscribedProcedure Blocks Onboarding Completion (DEADLOCK)

**Severity:** CRITICAL
**Location:** `apps/api/src/trpc/routers/clinic.router.ts` — `completeOnboarding` procedure
**Root Cause:** `completeOnboarding` uses `subscribedProcedure` which requires an active subscription. But new admins need to complete onboarding before their subscription is fully set up, creating a chicken-and-egg deadlock. `getOnboardingStatus` correctly uses `protectedProcedure` (with comment: "must work before subscription exists"), but `completeOnboarding` doesn't follow the same logic.

**Required Fix:** Change `completeOnboarding` from `subscribedProcedure` to `protectedProcedure`.

## Key Insights

1. **Adversarial code reviews catch code bugs, not design bugs** — Reviews found ~45 code-level issues but never questioned whether the magic link flow matched the architecture spec. Process improvement: cross-reference PRD/Architecture during reviews.
2. **Unit tests don't replace real user journey testing** — 428 tests pass, but 3 critical bugs exist in the actual browser flow. E2E or manual test protocols needed.
3. **API convention consistency is critical** — Mixing Zsa tuple returns with TanStack Query direct returns creates silent runtime errors that TypeScript can't catch.
4. **MCP tools (Context7, Stripe plugin) must be used systematically** — Coding "from memory" leads to outdated patterns and missed best practices.
